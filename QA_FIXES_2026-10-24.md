## Limits and deployment follow-up

No live student records, scores, hours, credentials or photos were changed during verification. The browser was at login; authenticated live acceptance, evaluation submission and completion issuance need a follow-up QA run after sign-in. The page code and markup were compiled locally.

Configure Firebase Admin credentials and persistent media as described in `firebase/SERVER_CONFIGURATION.md`. Do not send or commit service-account JSON. Configure it directly on the server.

Seat reservation and placement creation use two stages: a conditional write limited to the opportunity, followed by the existing atomic multi-path PATCH for application/student/placement. On an uncertain network failure the reservation is retained and confirmation must be retried using the same offer. This avoids overbooking; it does not promise a single cross-record transaction. A future cancellation workflow must release reservations consistently. Existing historical occupancy is not bulk-written or silently migrated.
